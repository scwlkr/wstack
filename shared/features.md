# Features

`FEATURES.md` → root product vocabulary; link from `w.md`. Multiple apps → sections; feature files only when useful.
- Feature = intentional, distinct user-visible software aspect; bugs belong to affected feature.
- All features → recognizable names + 1–2 sentences covering behavior/controls/qualities.
- Rename → update descriptions/references; useful aliases only.
- Describe current features; label planned when useful; remove deleted entries (history in Git).
- Feature work → update affected entries; full discovery only when requested.
- Full discovery → code/docs/UI as needed; describing every feature ≠ operating/checking every feature.
- Detail follows task; no fixed proof/harness/gotcha sections or verification-status ledger.
- Common/project terms → compact dictionaries; link project glossary from `w.md`. Learn selectively from AI Hero; local vocabulary owns meaning.
