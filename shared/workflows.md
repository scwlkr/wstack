# Workflow details

Use when lifecycle, delivery or tooling needs clarification. The core in
`SKILL.md` carries the shared preferences and requirements; no planning ledger,
phase report or fixed sequence of artifacts is required.

## Choices and investigation

- Scale alternative approaches from short plans to working prototypes. The critic strengthens the nonpreferred route; main deliberates. Show useful comparisons, then proceed unless Shane requests selection first. Missing design subagents → main supplies alternatives + critique; this does not waive independent code review.
- Debug with a cheap reproduction or useful diagnostics; trace cause through informative experiments. Reconsider the premise when attempts stop yielding information.
- Explain meaningful departures within the goal; bring goal-changing choices or conflicting directions to Shane. Continue independent work.

## Environment and project tools

- Acquire relevant MCP/plugins/skills when needed; Apple apps → Xcode tooling. Unavailable access, payment or consequential shared changes → Shane.
- Reuse project CLI commands; favor fast, scriptable, repeatable controls, practical MCP/native/computer-use fallbacks. Add seed/reset/inspect/drive helpers only when they save total effort.
- Setup returns immediately; worker stops within 60s. Inspect status when useful, then discard it. Missing setup runtime → prepare the same small footprint directly: `w.md`, short agent pointer, CLI help and feature/glossary pointers. Preserve owner notes/commands; adapt retired generated routes only when needed.
- Keep useful project decisions in `w.md`; tracking only when helpful. Engineering defaults: clear names/direct flow, co-changing code together, files ≤300 lines unless splitting worsens design.

## Delivery and owner review

- Show a local build, screenshots or useful preview for release review. Owner blocked → seek attention through configured owner channels every minute until response; follow owner timing and continue independent work.
- A successful upload/job is insufficient for live delivery. Inspect the actual result and relevant side effects; a build alone does not prove behavior. Recheck only after changes that invalidate evidence; resolve required gates.
- Review-only → findings. Feature discovery describes features without requiring every feature to be operated or checked.

For review briefing, design selection or resource/artifact questions, consult the
matching [review](code-review.md), [design](design.md) or [maintenance](maintenance.md)
guide only as useful.
